What is a Claude Skill?

A skill is a single Markdown file (SKILL.md) that gives Claude Code a set of specialised instructions — like a job description for a very specific task. Once installed, Claude reads it automatically at startup and knows exactly how to handle certain requests.

Think of it as a plugin for Claude: instead of writing the same long prompt every time, you install the skill once and just say the trigger phrase. No code, no API keys, no configuration. Just a Markdown file in the right folder.

01 Installed Writing

Humanizer

Strips 29 AI writing patterns from any text — and rewrites it with an actual personality.

v2.5.1 · MIT

What it does

Most AI-generated text has tells: inflated significance, em-dash overuse, "at its core" filler, rule-of-three lists, promotional phrasing. Humanizer catches all 29 of these patterns, documented by Wikipedia's WikiProject AI Cleanup.

But it doesn't just strip the bad stuff. It adds voice back in — varying sentence rhythm, injecting opinions, acknowledging uncertainty like a real person would. Then it does a second pass: asks "what still sounds AI-generated?" and revises again.

If you give it a sample of your own writing first, it calibrates to your specific style — your sentence lengths, word choices, punctuation habits — so the output sounds like you, not like generic clean prose.

29 patterns detected

  • Significance inflation ("pivotal moment", "testament to")
  • Em dash overuse → replaced with commas or periods
  • Superficial -ing phrases (highlighting, underscoring)
  • Promotional language & AI vocabulary words
  • Rule of three / synonym cycling
  • Passive voice & copula avoidance
  • Filler phrases ("at its core", "the real question is")
  • Sycophantic openers ("Great question!")
  • False ranges ("from X to Y, from A to B")
  • Formulaic conclusions + double-pass audit

02 Installed Decision-Making

LLM Council

Runs any decision through 5 AI advisors who think from different angles, peer-review each other, then deliver a synthesised verdict.

Based on Karpathy · MIT

What it does

Claude is agreeable by nature. Ask "should I launch this?" and it finds reasons to say yes. Reframe the same question negatively and it finds reasons to say no. That's fine for writing emails — it's dangerous for real decisions.

The Council fixes this. It spawns 5 independent advisors, each with a fundamentally different thinking style. They all analyse your question without seeing each other's work. Then their responses are anonymised and each advisor peer-reviews the others. Finally, a Chairman synthesises everything into a verdict: where the council agrees, where it clashes, blind spots it caught, a clear recommendation, and one concrete next step.

Adapted from Andrej Karpathy's LLM Council methodology — originally about dispatching queries to multiple models. This version runs entirely inside Claude using sub-agents with different lenses.

How it runs

  • Step 1: Scans your workspace for context, frames the question
  • Step 2: Spawns all 5 advisors in parallel (no cross-contamination)
  • Step 3: Anonymises responses A–E, runs peer review round
  • Step 4: Chairman synthesises verdict from advisors + reviews
  • Step 5: Delivers structured output directly in chat (~4 minutes total)

The Contrarian

Actively looks for what's wrong, what's missing, what will fail. Assumes there's a fatal flaw.

First Principles

Strips away assumptions and rebuilds the problem from scratch. Often says "you're asking the wrong question."

The Expansionist

Looks for upside everyone else is missing. What could be bigger? What adjacent opportunity is hiding?

The Outsider

Zero context about you or your field. Catches the curse of knowledge — things obvious to you, confusing to everyone else.

The Executor

Only cares about: can this be done, and what's the fastest path? Looks at every idea through "what do you do Monday morning?"

03 Installed Meta

Task Observer

Watches every session silently and improves all your other skills automatically over time. Also known as "One Skill to Rule Them All."

CC BY 4.0 · rebelytics

What it does

Most skills stay frozen after you install them. Task Observer fixes that. It runs as a persistent background layer during every task-oriented session — watching for corrections you make, patterns that repeat, workflows that could be formalised.

Every time you correct an output, discover a better approach, or develop a structured process, it logs an observation. On a weekly cadence it applies these observations back to your skill library — improving humanizer, council, and skill-creator based on how you actually use them.

After three months of use, the original creator logged 600+ improvements across 40 skills — all generated automatically from real session observations.

How it works

  • Runs silently in the background — never interrupts your flow
  • Logs observations: user corrections, emerging patterns, new workflows
  • Weekly review applies improvements back to your skill library
  • Feeds skill-creator for new skills when patterns repeat enough
  • Works in claude.ai (handoff doc mode) and Claude Code (file system)
  • Self-improving — also improves its own methodology over time

04 Installed Claude Code

Superpowers

Turns Claude Code from a code generator into a disciplined senior developer — brainstorm first, spec second, build third. No exceptions.

v5.0 · MIT · obra

What it does

Claude Code by default jumps straight into writing code the moment you describe something. Superpowers stops that. It enforces a structured 7-phase workflow: brainstorm the idea, explore alternatives, write a spec, get approval, then build — with test-driven development throughout.

The result: Claude Code doesn't make autonomous decisions, doesn't expand scope, and doesn't declare success without proving things work. Every task has a plan detailed enough that a junior engineer could follow it. Every step gates the next.

Installed via the official Anthropic plugin marketplace. Activates automatically — no trigger needed. 170k+ GitHub stars, officially maintained.

7-phase workflow

  • Brainstorming — explores context, proposes 2–3 approaches, writes spec
  • Writing plans — breaks work into 2–5 min tasks with exact file paths
  • Execution — subagents implement each task, inspect their own work
  • TDD — enforces RED → GREEN → REFACTOR, no exceptions
  • Code review — checks against plan after each task, blocks on critical issues
  • Systematic debugging — 4-phase root cause process, no random guessing
  • Branch finishing — verifies tests, offers merge/PR/discard options
